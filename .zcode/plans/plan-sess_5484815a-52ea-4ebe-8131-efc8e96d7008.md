# 推送用户名/密码认证支持（仅 push、会话内存、失败后弹框重试）

## 需求与决策（已确认）
- 场景：部分老服务器 HTTPS 推送需要用户名+密码（ambient 系统凭据助手无缓存时，当前会卡到 300s 超时或报无出路的 Auth toast）。
- D1 凭据记忆：仅进程会话内存，关闭应用即清，不落盘（不违背 TDD R-23「不存储密钥」deferral）。
- D2 范围：仅 `push`（fetch/pull/clone 不动；但强推流程内部的 fetch/ls_remote 取 old_tip 属于同一次 push 操作，可复用同份凭据）。
- D3 触发：先按现有 ambient 方式推，收到 `Auth` 错误才弹凭据框，提交后自动重试一次；用户取消则收场不报错刷屏。

## 实现方案

### 后端 Rust（凭据注入点：`GitCli::run`，调用方仅 push 链路）
1. `eg-types/src/dto.rs` 新增 `PushCredentials { username: String, password: String }`（`Deserialize+Serialize+Type`，camelCase），`lib.rs` re-export。不新增 EgError 变体，复用 `Auth{provider:"git"}`。
2. `commands.rs::sync_push` 加参 `credentials: Option<PushCredentials>`（永不 log），透传 `push_with_rollback → push → run`；`run` 加可选 auth 配置参数，其余调用方（fetch/pull/clone/ls_remote/test）传 None，行为零变化。
3. `remote.rs` 新增 askpass 注入（push 调用时）：
   - 生成临时 askpass 脚本（Windows `.bat` / Unix `sh`，文件权限 0600，prompt 含 Username→回用户名、Password→回密码），子进程独占 env：`GIT_ASKPASS=<script>` + `GIT_TERMINAL_PROMPT=0` + stdin 接 null（失败快速返回，不再垂死 300s），跑完立即删除脚本；
   - 密码不进 argv、不进日志/lens record、不进 op-log/timeline；内存 String 用后 drop（可选项：引入 zeroize 做擦除）。
4. 强推的预检 fetch/ls_remote 复用同一份 creds（同一次操作内）；undo 强推（`push_restore`）保持 ambient，记为已知局限（见 §风险）。

### IPC 与前端
5. `sync_push` 改签名 → 跑 `cargo run --features gen-bindings --bin generate-bindings` 重生成 `bindings.ts`（CI 卡漂移）；`lib/ipc/commands.ts::pushRemote` 加可选 `creds` 形参。
6. `syncStore.ts`：内存 `Map<repoId+remote, {username,password}>`（先核实 store 无 zustand/persist 落盘）；`push()` 保持首次 ambient 调用，catch `code==='auth'` → 有记忆凭据则直接重试，无则打开新凭据对话框 → 提交后重试 → 成功则记入内存。新增返回 `'cancelled'`（用户关框），`SyncButtons.tsx` 遇到 cancelled 直接收场（不 toast、不开强推框）。
7. 新组件凭据对话框（仿 `SyncButtons` 强推/`CloneDialog` 模式：用户名明文 + 密码 `type=password` + 中文文案遵 PRD §6.7），附“本窗口关闭/应用退出即忘，不存储”说明。顺手把 `errors.ts` 里 `auth` 的死 hint `open-credentials` 接到该对话框（让旧 toast 的“管理凭据”按钮活过来）。
8. `record('git push ...')` 等 lens 日志严禁拼接凭据；密码框禁止自动填充/日志。

### 测试
9. Rust：askpass helper 单元测试（prompt→应答映射、0600 权限、用后删除）；`w9_remote_sync.rs` 风格新增：带 creds 推 `file://` bare origin 成功（证明注入链路不破坏正常推送）+ 撤销锚点不断言回归。
10. 前端 `syncStore.test.ts`：mock `pushRemote` 首次抛 auth、二次成功，断言重试参数带 creds、cancelled 路径无 toast；`errors.test.ts` 不动（无新 code）。

### 文档
11. TDD R-23 偏差日志补一行：会话内存凭据 + askpass 临时脚本仍属“不存储”，keyring 托管仍 defer；`SettingsPage` 的 Network 占位文案不动。

## 风险与取舍
- `undoOperation` 强推回滚仍走 ambient：在需认证服务器上 undo 可能失败。治本要给 undo 也加可选 creds（改共享命令签名），本次为控范围先记局限 + toast 引导重推；若你希望一次做彻底，工作量约 +30%。
- Windows `.bat` 回显密码经 env 传给子 git：同机其他进程理论可见，属 askpass 通用权衡；缓解是脚本/进程生命周期最短 + 立删。接受与否请确认（默认接受）。
- 无真实老服务器联调：以 file:// 回归 + askpass 单测 + 手工对测试服验证为准。
