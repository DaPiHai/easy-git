# 修复 Windows 上 git 操作与空闲维护闪现空白 cmd 窗口

## 根因（已定位，非猜测）

- `src-tauri/src/main.rs:2` 在 release 下是 `windows_subsystem = "windows"`：进程没有控制台。
- `git.exe` 是控制台程序。`std::process::Command::spawn` 未传 `CREATE_NO_WINDOW` 时，Windows 会为这个子进程**新建一个可见的控制台窗口** → 用户看到的空白 cmd 黑框。
- 全工程只有 **2 处**生产级外部进程调用，都是 git CLI：
  - `src-tauri/crates/eg-git-core/src/remote.rs:217`（`GitCli::run`）：fetch / pull / push / clone / ls-remote / `git gc`
  - `src-tauri/crates/eg-git-core/src/diff.rs:460`（`apply_to_index`）：逐行/逐块暂存的 `git apply`
- 「空闲时每隔一段时间」精确对应 `worker.rs:723` 的 `MAINTENANCE_IDLE = 300s`：仓库空闲 5 分钟后静默跑一次 `git gc --quiet`（`remote.rs:323`），每个打开的仓库各一个 worker 线程，所以是周期性闪现。
- 其他所有操作走 git2-rs（进程内 libgit2），不会弹窗——这解释了为什么只有「网络操作 + 逐行暂存 + 空闲维护」会闪。
- dev 模式（`pnpm tauri dev` / debug）`main.rs` 的条件编译不生效，父进程自带控制台，子进程继承它、不会新建窗口，**因此本地开发从没复现过**。这也是为什么必须用 release 包验收。

## 改动（最小、集中、可回归）

1. **新增** `src-tauri/crates/eg-git-core/src/process.rs`
   - `pub fn hidden_command(program: &str) -> std::process::Command`：Windows 下加 `CommandExt::creation_flags(0x0800_0000 /* CREATE_NO_WINDOW */)`，其他平台原样返回。
   - 注释写清为什么不用 `DETACHED_PROCESS`：完全没有控制台时，孙进程（`GIT_ASKPASS` 的 `askpass.bat` 要经 cmd.exe）会各自新建**可见**控制台；`CREATE_NO_WINDOW` 给的是隐藏控制台，会被后代继承，所以能一并盖住凭据助手。
   - 内联测试：跨平台 `git --version`（保证加了 flag 仍能正常 spawn，也覆盖非 Windows 直通路径）；Windows 下再跑 `cmd /C echo ok` 成功。
2. `src-tauri/crates/eg-git-core/src/lib.rs`：注册 `pub mod process;`（按现有字母序插在 `ops` 与 `refs` 之间）。
3. `remote.rs:217`：`std::process::Command::new("git")` → `crate::process::hidden_command("git")`，其余参数、stdout/stderr 管道、`GIT_TERMINAL_PROMPT`、askpass 逻辑全部不动。
4. `diff.rs:460`：同样改用 `hidden_command("git")`；顺手把当前未设置的 stdout 显式设为 `Stdio::null()`（修复后子进程已无控制台可写；`git apply` 成功不输出，只校验 status/stderr，不影响现有行为）。
5. 文档一行：`docs/easy-git-tdd.md` §4.2 CLI 桥接处补「所有控制台子进程统一经 `eg_git_core::process::hidden_command` 创建（Windows 传 `CREATE_NO_WINDOW`）」，给后来者立规矩；`AGENTS.md` 已知注意事项加一行。

## 不做的事

- 不动 `windows_subsystem`（那是正确的，正是它导致子进程必须显式抑制控制台）。
- 不动测试里的 git 调用：`cargo test` 本身带控制台，子进程继承，不会弹窗，也不影响用户。
- 不改任何命令签名 → **不涉及 bindings 漂移**，无需跑 generate-bindings。

人工验收（**必须 release 包**，`pnpm tauri build` 或 `cargo build --release` 后运行 exe）：
1. 打开一个仓库 → 点「获取 / 拉取 / 推送」→ 观察无黑框；
2. 对某文件做逐行暂存（R-13 路径，走 `git apply`）→ 无黑框；
3. 让窗口空闲 ≥5 分钟 → 无黑框（想快验可临时把 `MAINTENANCE_IDLE` 调成 10s 跑一次，验完改回）；
4. 每个打开仓库都验一遍（worker 是按仓库起的）。
dev 模式不复现，**不能**作为验收依据。

## 风险与回退

- 若用户的 Win11 把「默认终端应用」设为 Windows Terminal，存在系统级已知的瞬闪现象（即使传了 `CREATE_NO_WINDOW`）。若 release 包验证后仍闪，回退方案是调整系统默认终端为「Windows 控制台主机」或另做评估，**不会**改用 `DETACHED_PROCESS`（会引出更多可见窗口）。
- `CREATE_NO_WINDOW` 只影响控制台分配，不影响 git 的网络、凭据助手、SSH agent 行为。
