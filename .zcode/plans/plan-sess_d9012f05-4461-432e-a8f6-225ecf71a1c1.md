# 为所有 git 操作加等待动画

## 已定取舍

- 呈现：窗口顶部 2px 不确定进度条（全局可见）+ 底栏具体操作提示 + 触发按钮转圈。
- 覆盖：用户发起的**写操作 + 网络操作**显示；**只读/后台调用静默**（不重蹈 rc.2 刚修的「后台刷新闪蓝线」）。
- 文案：每个操作显示具体名称（「正在切换分支…」），未映射的回落「正在处理…」。

## 设计

### 1. 新增 `src/stores/busyStore.ts`（引用计数 + 标签栈）
- `begin(label: MessageKey) => end()`：压入 `{id,label}`，`end()` 按 id 精确移除且幂等；重叠操作时 `label` 取栈顶，`busy = stack.length > 0`。这解决现有各 store 用单布尔量、并发时会被提前清掉的通病。
- **150ms 延迟显示 + 最短展示 300ms**：瞬时操作（暂存、切换分支这类 <150ms 的）完全不闪；超过阈值才亮起，亮起后至少停留 300ms，避免一帧闪烁。

### 2. 在 `src/lib/ipc/commands.ts` 统一包装（单一收口）
现有导出体是统一形状，只需把那一行 invoke 包起来，改动最小：
```ts
const result = await tracked('branchSwitch', () => commands.branchSwitch(repoId, name));
```
- `tracked(name, run)`：`begin(LABELS[name] ?? 'busy.generic')` → `await run()` → `finally end()`。
- **只包写/网络命令**，只读命令一行不动 —— 静默是默认，将来新增命令不会误闪。
- 约 33 处一行包裹，全在一个文件里；`CloneDialog` 也是走 `commands.ts` 的 `cloneRepo`（已确认），所以克隆同样被覆盖。

### 3. 覆盖清单

显示（33）：`openRepo` `initRepo` `closeRepo`、`stagePaths` `stageLines` `discardChanges` `cleanExecute` `ignorePaths`、`undoOperation` `redoOperation` `restoreTo`、`commitIndex` `setConfig`、`branchCreate` `branchRename` `branchDelete` `branchSwitch` `branchSetUpstream`、`tagCreate` `tagDelete`、`stashPush` `stashApply` `stashDrop`、`mergeStart` `mergeAbort` `conflictResolve` `revertCommits` `resetCommits`、`fetchRemote` `pullRemote` `pushRemote` `remoteTest` `cloneRepo`、`remoteAdd` `remoteRename` `remoteRemove` `remoteSetUrl`。

静默（保持不动）：`getStatus`（fs-watch + Ctrl+R，已有 `statusLoading` 蓝线）、`logPage` `commitDetail` `diffFile`（各自页面已有加载态）、`mergeStateGet` `conflictsGet` `remoteList` `remoteBranchList` `undoRedoState`（轮询/派生刷新）、`branchList` `tagList` `stashList` `timelineGet` `cleanPreview` `getConfig` `getAppVersion` `pickDirectory`。

### 4. 三个呈现位
- **全局顶栏条**：新增共享 `src/components/LoadingBar.tsx`，把现在 `ChangesPage.tsx:198-208` 与 `HistoryPage.tsx:57-61` 重复的那段（`h-0.5` + `w-1/3 animate-pulse bg-primary` + `role="progressbar"`）提取出来；在 `AppShell` 根节点内**绝对定位** `top-0 inset-x-0 z-50` 渲染（根加 `relative`），避免出现/消失时把布局顶动 2px。
- **底栏提示**：`BottomBar.tsx` 的状态区（现「暂无后台任务」处）——有网络 `progress` 时保持现状（带百分比，优先）；否则 `busy` 时显示 `⟳ 正在切换分支…`（`Loader2` + `animate-spin`，`data-testid="busy-strip"`），并给状态区加 `aria-live="polite"`。底栏是 UI 规范 §5.1 指定的任务进度宿主，不新造位置。
- **按钮转圈**：`src/components/Button.tsx` 新增可选 `loading?: boolean`，为 true 时渲染 `Loader2`（`animate-spin`）+ 保留原标签（宽度不跳）+ 自动 disabled。接入点：`SyncButtons`（获取/拉取/推送用现有 `busy`）、`RemotesPage`（测试连接/获取）、`CloneDialog`（确认按钮用现有 `busy`），顺手给 `CommitBox` 那个原生 `<button>`（已有 `submitting`）内联一个 spinner。

### 5. i18n
在 `src/lib/i18n/zh-CN.ts` 增加 `busy.*` 一组（约 30 个短文案，如 `busy.branch.switch`=正在切换分支…、`busy.commit`=正在提交…、`busy.fetch`=正在获取…），加 `busy.generic`=正在处理… 兜底；措辞沿用现有「正在…/…中」风格。

### 6. 文档
在 `docs/easy-git-ui-design.md` 补三条规格：§6.1 按钮加载态、§5.1 底栏等待提示、§6.11 全局不确定进度条（2px、`primary`、`animate-pulse`），使实现与「ui-design 是实现标准」一致。

## 不做 / 风险
- 不动 Rust 侧，不给 `status_get`/`log_page` 这类只读调用加全局等待（否则退回蓝线乱闪）。
- 不加全屏遮罩（UI 规范把遮罩留给弹窗/向导，且会阻断操作）。
- 风险低但需确认：`animate-spin` 在 Tailwind v4 下是否可用（现有 `animate-pulse` 可用，预期没问题）；`prefers-reduced-motion` 全局降级已存在，动画会自动尊重。
